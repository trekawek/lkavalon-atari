Wladcy Ciemnosci semantic-name recovery
======================================

Names in this pass follow the released code, callers, state tables, action
labels and Atari memory accesses. Descriptive aliases are explicitly inferred;
they do not restore erased original spellings. Saved headers, addresses,
instructions and resource bytes remain unchanged.

symbols.txt records per-word evidence, stack effects and decoded callers.
Edit tools/inferred-names.json for persistent manual naming evidence;
make decompile merges it with recovered names and regenerates the Forth,
dictionary.json, symbols.txt and string-catalog owner names. Caller lists
cover decoded colon calls and COMPILE operands. Native references, raw DOES>
tails and data-driven action dispatch can add other uses.

MEMORY MAP AND EXECUTABLE CHECKS

The cursor uses the Atari OS column cell at $55 and row byte at $54. Joystick
conversion at $50B2 accepts a controller number, reads its STICK0 shadow byte
at $0278+controller, then decodes movement. AD2044 instead expects a raw
joystick value. Trigger reads use GTIA $D010+controller, mask bit zero and
return zero when pressed; they do not read the OS trigger shadow.

The action-record pointer is stored at $66EE. $6777 adds a byte offset and
two to skip the record's 16-bit length; $6789 reads the selected byte.
$6D31/$6D40 fetch and store puzzle-state cells indexed from $5806, using the
DOES> array at $5802. These field interpretations are checked by executing
the original routines with distinct values at adjacent positions.

Object/frame splitting at $6F89 uses decimal hundreds: it returns n modulo
100 and twice the quotient n/100. This represents resource/frame selection,
not a division by hexadecimal $100.

The eight records at $5517 belong to the SPIS MOCY power list. The five-slot
inventory is instead room 0/view 1 of the mutable object table at $564E.
All 80 action slots were checked, including shared handler targets. Path-puzzle
tests verify the four 16-bit counters, move budget and accepted-predecessor
rule; an invalid transition stores 100 in its direction counter.

Some Klątwa routines remain in this image. Their presence does not establish
active gameplay: the four-item-room logic at $6EA0/$6EE0 expects rooms 25..28
and message data at a resource occupied here by a picture. Its reachability
is not established; it is described as retained logic, not a confirmed quest.

Semantic tests execute the original 6502 instructions and Forth dispatcher
from the released disk. They check all nine joystick positions on four
controllers, trigger bits, cursor storage, strict signed range boundaries,
first-match byte search, action fields, puzzle cells, inventory operations,
resource IDs, banked spans, object/frame parts and directional puzzle steps.
The selected bounded routines require no OS stubs or simulated interrupts.
These checks support individual meanings, not a claim of full gameplay
coverage or an identical implementation in another game.

AUTHOR TUTORIAL COMPARISONS

The eleven supplied installments provide evidence about the author's Forth
conventions and several shared facilities. They are not the missing game
source screens. The preserved GAM sources provide further comparisons;
structural similarity alone does not prove an original name.

Issues 1-4/92 describe variables, allocated buffers and Boolean operations.
Stale text inside allocated storage is not automatically an active message.
The introductory PAUSE resets the clock; this game's $42A2 waits for changes
of the low RTCLOK byte $14.

Issue 5/92 and issue 11-12/92 corroborate the cursor family at
$39F0/$39FE/$3A0C/$3A1A/$3A29. Complete bodies and surviving header characters
support the identification, and direct runtime probes verify the OS fields.

Issue 6-7/92 supplies <=<, matching $38F4. The actual threaded body uses
strict signed comparisons: lower < value < upper. The tests include both
bounds and negative values, rather than assuming an inclusive bound from
the word's spelling.

Issues 8-10/92 explain assembler conventions, X as the downward-growing
parameter stack pointer, two-byte cells, NEXT/POP/POPTWO and JSR/RTS routines.
These distinctions guide the native-code analysis. The reconstruction's
separate prefix assembler specifies operand width to preserve absolute
instructions even when their addresses are below $0100.

Issue 11-12/92's INSTR scans backward. The game's byte search at $3896 returns
the one-based first match, as a repeated-character probe confirms. Related
interfaces do not justify treating these implementations as identical.

Issue 1-2/93 describes access to RAM underneath OS ROM. It supplies useful
conventions, but does not by itself establish a game's erased identifiers.
